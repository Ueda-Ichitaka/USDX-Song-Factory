3. Lyrics mode: fitting known lyrics to the vocals

The same code builds the notes of every new song with online lyrics and every repair in lyrics mode (repair.py --mode lyrics). The admin files on the right change single steps.

4. Repairing a song, step by step

A repair works on a copy: the folder in input/ is never changed. The mode (section 5) decides which of the three lanes runs; gap and sync keep the song's own notes and lyrics, lyrics mode rebuilds the notes from a trusted text.

5. How a repair job picks its mode

A folder in input/ becomes a repair job. build_job_plan() matches it to a broken.csv row and picks the mode in this order; the first matching row wins.

ConditionModeWhat happens
lyrics.txt in the folderlyricsfigure 3 with that text
category gapgaponly #GAP is re-detected from the first lyric lines
category asyncsyncevery line aligned in its own window (progressively_align, re-anchor, rescue); if lyrics and audio do not match (detect_lyrics_mismatch), the song is re-created with UltraSinger (REPAIR_FALLBACK)
category lyricslyricslyrics_fetch.py first (report's lyrics_url, else search); nothing found fails the job
category video / audiomedia, then gapfile already fine: needs review; one loose file in the folder: tag linked; a .usdb sync-meta file: media downloaded with yt-dlp; else failed
category other or emptynonelisted under "Needs review" in the report
no broken.csv rowREPAIR_MODEdefault sync

Every finished repair then runs romanize.py and the report's cover_url, like a new song. The input folder is never changed; the result is a full copy in output/repaired/.

8. Building the images

Rebuild after changes to src/, pyproject.toml, stack/Dockerfile or the usdb_syncer submodule; stack/orchestrator/ is mounted and needs none. From inside stack/:

docker compose build ultrasinger                        # CPU image  ultrasinger-stack:cpu
docker compose --profile rocm build ultrasinger-rocm    # ROCm image ultrasinger-stack:rocm
docker compose --profile rocm build --pull --no-cache ultrasinger-rocm   # from scratch

Details, restart and the check whether an image matches your code: stack/docs/development.md, section "Building the images".
