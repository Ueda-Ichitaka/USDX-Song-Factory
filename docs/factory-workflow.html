What goes in

song-requests.csv

new songs

The dashboard's song-request export; one row is one new song.

Needed
band, title and a YouTube link, or videos/<file> for a song not on YouTube (skip leaves the row out)
Best
language and musicbrainz_id on every row: no guessed language, and a video outro can be cut
Optional
lyrics_url (a link or a file in songtexts/), cover_url, genre (becomes #GENRE), trait (harsh_vocals, loud_high_instruments), duet (not built yet)

broken.csv + repairs/

repairs

Every folder in input/repairs/ is one repair; its broken.csv row (matched by #ARTIST/#TITLE) decides what is done.

gap
only #GAP is re-detected
async
sync: every line re-aligned, lyrics kept; re-created from the audio when the lyrics don't fit
lyrics
trusted lyrics (lyrics_url, else online) aligned in place of the old text
media
video/audio: the missing file restored, then a gap check
cover
only the cover, from cover_url
none
other/empty: "needs review"; no row: REPAIR_MODE (sync)

Files next to a song

repairs

Put into a folder in input/repairs/ to steer its repair.

lyrics.txt
trusted lyrics: lyrics mode
song_end.txt
nothing after this time is used for the lyrics
anchors.txt
pins line starts and the end
language.txt
wins over every other language source

What the report tells you

output/report.md is written at the end of every run; orchestrator.py report writes it again without running anything. A section appears only when it has songs.

Running a batch

  1. Export

    Save the dashboard's song-requests.csv into stack/input/; rows already done are skipped, so a full export is fine. Keep the "Reported" export (broken.csv) in Downloads: the next step merges it, so the rows already in stack/input/broken.csv stay.

  2. Prepare 
    python3 utilities/import_local_media.py --apply          # local song files into input/videos/
python3 utilities/copy_reported_songs.py --library /dhuaddan/media/ultrastar/songs \
  --csv ~/Downloads/broken.csv --apply                     # reported songs into input/repairs/

    More ways to fill input/repairs/: the utilities overview.

  3. Start 
    cd stack
docker compose --profile rocm up -d ultrasinger-rocm        # AMD GPU; ultrasinger for CPU only
docker compose --profile rocm exec ultrasinger-rocm progress -w   # live progress

    Only some jobs: orchestrator.py run --only generated|usdb|repairs or --match TEXT. Stop after the current song: docker compose --profile rocm attach ultrasinger-rocm, then stop.

  4. You check

    Read output/report.md, then sing the new and repaired songs in USDX. Write down the exact name of every song that drifts.

  5. Copy in

    Copy the folders of output/new/ and output/repaired/<repair>/ into the library.

  6. Fix and redo 
    docker compose --profile rocm run --rm ultrasinger-rocm \
  python /app/orchestrator/orchestrator.py reset                         # retry failed jobs
docker compose --profile rocm run --rm ultrasinger-rocm \
  python /app/orchestrator/orchestrator.py reset --done --match "Song"   # redo one song
