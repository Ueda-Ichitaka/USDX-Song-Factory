Library utilities workflow

Host tools that find broken songs in the UltraStar library, hand them to the stack for repair, bring dashboard reports and local song files into the stack input, and get the repaired songs back into the library. The genre tools have their own overview.

The tools

run_library_check.sh

reads library

Measures every song the way the stack's gap/sync repair does: the song file's own lyrics aligned to its separated vocals.

Runs
library_check.py in the stack's ROCm container (GPU); 20-45 s per song, a whole library takes many hours; stop with docker stop library-check, the same command continues
Writes
library analysis/results.jsonl (one line per song file) and library-check.txt (the report), every 10 songs
Verdicts
#GAP off, drifts, unclear, damaged audio, good; left out: duets, relative timing, no #BPM, no audio, under 50 notes, the stack's own songs, audio over 15 min
Limits
MEMORY, CPUS, MIN_AVAIL_GB, MAX_LOAD; never at the same time as a stack batch

import_broken_songs.py

reads library

Hands the songs the check found broken to the stack.

Reads
results.jsonl: verdicts #GAP off (category gap) and drifts (async); --categories narrows it
Writes
song folders into stack/input/repairs/ (existing ones left alone); broken.csv rows in the dashboard format with the measured fix as description (backup kept)
Then
runs fill_lyrics_links.py for rows without a lyrics link (--no-lyrics skips it)
Safe
dry run unless --apply

fill_lyrics_links.py

online

Finds a lyrics link for every broken.csv row with an empty lyrics_url; rows with a link are never touched.

Asks
  • lrclib.net: artist and title match, length within 4 s of the song's own audio
  • Genius, with GENIUS_API_KEY
  • lrclib.net free-text search, with the same length check
Writes
the lyrics_url cells of stack/input/broken.csv
Safe
dry run unless --apply; 1 s between songs

copy_reported_songs.py

reads library

Brings the songs reported on the dashboard's "Reported" page into the stack.

Reads
one or more broken.csv exports (--csv); finds each Band - Song folder in --library, any case
Writes
the folders into stack/input/repairs/; the rows merged into stack/input/broken.csv (backup kept, no duplicate rows)
Lists
rows without a library folder
Safe
dry run unless --apply

import_local_media.py

reads files

For songs that are not on YouTube: copies the audio or video file a song-list row names into the stack input, which the container can see.

Reads
paths in song-requests.csv: absolute paths, smb:// and \\host\share on a mounted share, --map for Windows drives
Writes
the files into stack/input/videos/ (own name; same name and size reused, otherwise " (1)"); the row becomes videos/<file> (backup kept)
Untested
nfs:// and shares that aren't mounted (gio copy): reference code, open for contribution

Copy back

writes library

Not a tool: you copy the repaired song folders from stack/output/repaired/<repair>/ into the library.

Dolphin
drop the folders onto the library, "Write Into", "Apply to All", "Overwrite older files": only the fixed song file is newer, the media is skipped
Check
in recreated/ a folder can hold a second song file (USDX would list the song twice); language.txt is extra, USDX ignores it

Run order

  1. Scan 
    utilities/run_library_check.sh /dhuaddan/media/ultrastar/songs
docker logs -f library-check        # progress
  2. You check

    Read library analysis/library-check.txt. #GAP off and drifts come with the fix; listen to unclear songs before changing anything; replace damaged audio files.

  3. Import 
    python3 utilities/import_broken_songs.py --library /dhuaddan/media/ultrastar/songs           # dry run
python3 utilities/import_broken_songs.py --library /dhuaddan/media/ultrastar/songs --apply

    Dashboard reports instead or as well: copy_reported_songs.py --library ... --csv ~/Downloads/broken.csv --apply, then fill_lyrics_links.py --apply.

  4. Local files 
    python3 utilities/import_local_media.py --apply      # after every song-requests.csv export
  5. Repair 
    cd stack
docker compose --profile rocm run -d --name repairs-run ultrasinger-rocm \
  python /app/orchestrator/orchestrator.py run --only repairs
docker exec -it repairs-run progress -w

    The whole stack run is described in the factory overview.

  6. Copy back

    Read stack/output/report.md, then copy the folders of stack/output/repaired/<repair>/ into the library (Dolphin: overwrite older files only).
